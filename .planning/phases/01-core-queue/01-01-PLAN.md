    **Private members (per STRC-03, SAFE-02):**
    ```cpp
    std::deque<std::unique_ptr<T>> _queue;
    mutable std::mutex _mutex;
    std::condition_variable _cv;
    bool _active{true};
    ```
    Note: `_active` is a plain bool (not atomic) because ALL reads go through the mutex. The only exception is `is_open()` which reads under lock too per D-06/D-07 consistency pattern. Do NOT use `std::atomic<bool>` -- the mutex provides the memory ordering.

    **Public interface (per SAFE-03):**
    ```cpp
    inspectable_mpsc() = default;
    ~inspectable_mpsc() = default;
    inspectable_mpsc(const inspectable_mpsc&) = delete;
    inspectable_mpsc& operator=(const inspectable_mpsc&) = delete;
    inspectable_mpsc(inspectable_mpsc&&) = delete;
    inspectable_mpsc& operator=(inspectable_mpsc&&) = delete;
    ```

    **Methods:**

    `[[nodiscard]] bool push(std::unique_ptr<T> item)` (CORE-01):
    - Lock mutex. If `!_active`, return false. Move item into `_queue` via `push_back`. Notify one waiter on `_cv`. Return true.

    `template <typename... Args> [[nodiscard]] bool emplace(Args&&... args)` (CORE-02):
    - Lock mutex. If `!_active`, return false. `_queue.push_back(std::make_unique<T>(std::forward<Args>(args)...))`. Notify one on `_cv`. Return true.

    `std::unique_ptr<T> pop()` (CORE-03, per D-03 -- true blocking, NO polling):
    - Lock mutex. `_cv.wait(lock, [this] { return !_queue.empty() || !_active; });`. If `!_active && _queue.empty()`, return nullptr. Move front element via `std::move(_queue.front())`, `_queue.pop_front()`, return it.
    - IMPORTANT: If `_active` is false but queue is non-empty, still return the front item (drain remaining). Only return nullptr when inactive AND empty.

    `std::unique_ptr<T> try_pop()` (CORE-04):
    - Lock mutex. If `_queue.empty()`, return nullptr. Move front, pop_front, return.

    `void interrupt()` (LIFE-01):
    - Lock mutex. Set `_active = false`. Unlock. `_cv.notify_all()`.

    `void reactivate()` (LIFE-02):
    - Lock mutex. Set `_active = true`.

    `void drain()` (LIFE-03):
    - Lock mutex. `_queue.clear()`.

    `[[nodiscard]] bool is_open() const noexcept` (STAT-01):
    - Lock mutex. Return `_active`. (Per D-06/D-07 consistency -- all state reads acquire lock.)

    `[[nodiscard]] bool is_empty() const noexcept` (STAT-02, per D-07):
    - Lock mutex. Return `_queue.empty()`.

    `[[nodiscard]] std::size_t size() const noexcept` (STAT-03, per D-06):
    - Lock mutex. Return `_queue.size()`.

    Note on `noexcept`: `std::mutex::lock()` can throw `std::system_error` but this is practically impossible in normal operation. Keep `noexcept` to match `interruptible_mpmc` convention. The `const` methods use `mutable` mutex.

    **WebKit brace style** (opening brace on same line):

    ```cpp
      std::unique_lock<std::mutex> lock(_mutex);
      ...
    }
    ```

|----------|-------------|
| Producer threads -> queue | Multiple producer threads push items through public API |
| Queue -> consumer thread | Single consumer thread pops items through public API |
