<objective>
Remove `target_bytes` from the downgrade API surface and update all callers.

Purpose: The `target_bytes` parameter on `request_downgrade` and `downgrade_request` is unnecessary — the predicate already defines the stopping condition. Removing it simplifies the API and prepares for the provider-based processing loop in Plan 02. Also extends the constructor to accept optional task queue references needed for tiered fallback.

Output: Updated API with no `target_bytes`, all callers migrated, all tests passing.
</objective>
