## Lifetime / Pitfall 5 Verification

The plan flagged Pitfall 5 (lifetime hazard): `cudf::io::source_info{datasource.get()}` stores a raw pointer; the `chunked_parquet_reader` holds the options for its full lifetime; `datasource` is a `unique_ptr<cudf::io::datasource>` that MUST outlive the reader; `uring_io_object` is the shared_ptr the datasource observes and MUST outlive the datasource.

Mitigation: declare in this order inside the loop body, then let block-scope reverse-destruction handle teardown:
1. `auto io_object = std::make_shared<sirius::io::uring_io_object>(path);` — declared FIRST, destroyed LAST
2. `auto datasource = target_ioctx->make_datasource(io_object);` — declared SECOND, destroyed SECOND
3. `cudf::io::chunked_parquet_reader reader(chunk_read_limit, opts);` — declared LAST (further down inside the same loop body), destroyed FIRST

Reverse-destruction order at end of each loop iteration: reader → datasource → io_object. Each round-robin iteration is fully self-contained; no cross-iteration aliasing.

The 46-assertion `[pin_mgpu]` PASS exercises this lifetime under SF1 conditions (multi-file, multi-chunk-per-file, 2-GPU round-robin); no leaks, no use-after-free observed.
