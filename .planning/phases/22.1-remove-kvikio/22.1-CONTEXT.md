<domain>
## Phase Boundary

Migrate every Sirius parquet/metadata read from cudf's bundled `file_source` factory (which uses kvikio internally) to `sirius_ioctx::make_datasource(io_object)`. After this phase, the following invariant holds in `src/`:

```bash
grep -rn 'cudf::io::datasource::create\|cudf::io::source_info{' src/ \
  | grep -v 'data_source\.get()\|datasource\.get()\|^[^:]*:.*//'
# → must return zero hits
```

**Why kvikio breaks multi-GPU:** kvikio's `FileHandle::pread` thread pool binds workers to a single CUDA context per FileHandle. When the destination buffer lives on a different GPU than the FileHandle's bound context, the resulting `cuMemcpyHtoDAsync_v2` either races (sanitizer reports it as cross-stream stream-ordered race — Cluster A in 22-VERDICT.md §K.1) or fails outright with `cudaErrorInvalidDevice`. This means **kvikio is incompatible with multi-GPU residency by design**. Phase 22's PIN-MGPU-01 round-robin distribution is necessary but not sufficient — until kvikio is removed, multi-GPU correctness cannot be guaranteed.

Out of scope:
- Changes to cucascade — kvikio is in the cudf chain, not cucascade. Cucascade pin stays at `c666b21`. (If discovery uncovers cucascade-internal kvikio usage, surface as `RESEARCH BLOCKED`.)
- Cucascade upstream PR (CC-UPSTREAM-01) — local pin only this milestone.
- Multi-GPU residency for iceberg metadata reads — single-GPU ioctx is sufficient for 22.1; per-GPU residency for iceberg becomes a renamed follow-up (see Deferred Ideas).
- New IO backends (e.g., GDS, S3) — only sites that currently hit cudf's bundled factory are in scope.
- HYG-02 line-count changes — must remain 40 phase-wide (preserved invariant from Phase 19).

</domain>

### Migration pattern (canonical, already proven in `parquet_scan_task.cpp:350,930`)
- **D-02:** Replace every `cudf::io::datasource::create(path)` with:
  ```cpp
  auto io_object  = std::make_shared<sirius::io::uring_io_object>(file_path);
  auto datasource = ioctx->make_datasource(io_object);   // returns sirius_datasource
  // Then in reader options: cudf::io::source_info{datasource.get()}
  ```
- **D-03:** Replace every `cudf::io::source_info{file_path}` (string-form constructor) with `cudf::io::source_info{datasource.get()}` (pointer-form constructor) where `datasource` is built from the canonical pattern above.

### Per-site scope decisions
- **D-04:** Site #1 (`sirius_gpu_parquet_scan_operator`) — plumb per-GPU `gpu_ioctxs` map through the operator constructor. Wire from `sirius_pipeline_converter` and `sirius_scan_manager` (mirrors how `parquet_scan_task_global_state` already accepts the map). Routing key: the chunk's `memory_space*` device_id (the per-chunk space added in Phase 22 22-01 PLAN). This kills K.1 (Cluster A) at SF1 Q11 num_gpus=2.
- **D-05:** Site #2 (`PinTableFunction`) — Phase 22's round-robin loop already binds the target device via `rmm::cuda_set_device_raii` and selects `target_space`. Add: acquire `sirius_ioctx` for `target_gpu_id` via `SiriusContext::get_ioctx_for(device_id)`; build `uring_io_object` per file; replace `source_info{path}` with `source_info{datasource.get()}`. The chunked-parquet reader API accepts `source_info{datasource_ptr}` — confirmed by canonical pattern.
- **D-06:** Sites #3+#4 (iceberg metadata reads) — use the **GPU 0 sirius_ioctx** for both the equality-delete `read_parquet` call and the footer extraction `read_parquet_footers` call. Single-GPU ioctx is sufficient because these are planning-time / pre-execution reads that are currently single-GPU-correct on GPU 0. Multi-GPU residency for iceberg metadata is deferred (see Deferred Ideas — replaces former IO-MGPU-02 with IO-MGPU-04).
- **D-07:** Sites #5+#6 (`datasource_factory` file:// + bare-path bypasses) — delete both fallback branches. The factory must always go through `registry.lookup(p.scheme) → ioctx → make_datasource(io_object)`. The startup path is responsible for registering an ioctx for `kFileScheme` (uring-backed). The bare-relative-path bypass (line 110) becomes: normalize the URI to `file:///<absolute>` if it lacks a scheme, then dispatch through the registry.
- **D-08:** Site #7 (`parquet_split_provider.cpp:295` unit-test fallback) — delete the `else` branch entirely. Inject a mock or real ioctx into unit-test fixtures. Production already passes `gpu_ioctxs`; the fallback exists only as a test-mode crutch.

### Factory policy (D-07 detail)
- **D-09:** When `datasource_factory::create()` cannot resolve a scheme to a registered ioctx, it **throws** `std::runtime_error("datasource_factory: no ioctx registered for scheme '<scheme>' — kvikio path is forbidden")`. This makes the kvikio-free invariant impossible to violate by future code: a developer adding a new scheme without registering an ioctx will hit this throw the first time the path is exercised.
- **D-10:** `kFileScheme` MUST be registered in `SiriusContext` initialization (current state: file:// has a bypass branch, no actual registration). Wire a `templated_ioctx`-derived uring ioctx for `kFileScheme` at startup. The existing per-GPU `gpu_ioctxs_` map is keyed by `device_id`; the file:// scheme should resolve to a per-GPU map instance, with the caller passing `preferred_device_id` to select the right one.
