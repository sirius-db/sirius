## Lookup Behavior — Static Contract

The runtime contract this plan establishes:

1. `datasource_factory::create_for_parquet_scan(uri, registry, config)`:
   - Empty URI → falls through to `create(uri, registry, config)`, which calls `parse(uri)`, which throws `std::invalid_argument("empty URI")`.
   - Relative bare path (no leading `/`, no `://`) → normalized to `file:///<absolute>` via `std::filesystem::absolute`, then dispatched through `create(normalized, registry, config)`.
   - Anything else (absolute path, `file:///...`, `s3://...`) → dispatched through `create(uri, registry, config)`.

2. `datasource_factory::create(uri, registry, config)`:
   - `parse(uri)` throws `std::invalid_argument` on malformed URIs (preserves existing parser strictness).
   - `registry.lookup(p.scheme)` returns the registered ioctx, or `nullptr` if the scheme is unregistered.
   - `nullptr` → throws `std::runtime_error("datasource_factory: no ioctx registered for scheme '<scheme>' — kvikio path is forbidden (uri=<uri>)")` (D-09 verbatim).
   - Resolved ioctx → constructs `std::shared_ptr<uring_io_object>(p.path)` and calls `ioctx->make_datasource(io_object)`. Returns the resulting `std::unique_ptr<cudf::io::datasource>` (which is actually a `sirius_datasource` wrapping the per-GPU io_uring backend).

After Plan 22.1-01 + 22.1-02 land, the only registered scheme is `kFileScheme` (string literal `"file"`). Object-store schemes (`s3://`, `gs://`, `azure://`) will throw the D-09 message on first use until a future plan registers their ioctx.
