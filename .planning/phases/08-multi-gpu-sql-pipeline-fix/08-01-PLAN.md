<objective>
Close FIX-01: replace `duckdb_scan_executor`'s single GPU-0-bound `_stream_pool` with a per-GPU stream pool map so that when `select_target_gpu()` returns GPU 1 (or any N>0), the scan task dispatches on a target-GPU-bound stream. This is the ROOT CAUSE of the v1.1 post-ship `cudaErrorInvalidValue` bug at `cuda_memcpy.cu:42` — allocations happen on GPU N's memory_space while the stream is bound to GPU 0, and cuDF's `cuda_memcpy` utility catches the mismatch.

Purpose: Phase 8 ship gate requires multi-batch TPC-H queries to execute correctly on `num_gpus: 2`. This fix unblocks W2 (FIX-02 probe), W3 (tests need a binary that doesn't crash), and W4/W5 (SF100 ship gate). All downstream work in Phase 8 depends on this fix landing first.

Output: Updated `duckdb_scan_executor.hpp` with a `_gpu_stream_pools` map member (replacing `_stream_pool`), updated constructor that populates the map per GPU, updated `manager_loop` dispatch site that acquires from the target-GPU pool after `select_target_gpu()` and wraps the lambda body in a `rmm::cuda_set_device_raii` guard.
</objective>
