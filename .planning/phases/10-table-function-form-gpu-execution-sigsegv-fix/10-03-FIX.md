# Phase 10 Plan 03: FIX — Stream Use-After-Destroy SIGSEGV

## Applied Hypothesis

**H1 confirmed** (from `10-02-GDB.md`): stream-ordered race in
`sirius_physical_parquet_scan.cpp` — the translator's scalar allocations
use a stream handle that is destroyed before the scalars are freed.

## Root Cause (refined from H1)

Plan 10-02 identified the H1 fault as a stream-ordered allocation race.
During implementation, the root cause was refined to a **use-after-destroy**:

1. `sirius_physical_parquet_scan` ctor creates a local `rmm::cuda_stream`
   (`translation_stream`) inside a `for (int device_id : ...)` loop.
2. `gpu_expression_translator` allocates `cudf::scalar` device buffers via
   `cudaMallocAsync` on `translation_stream`.
3. `translation_stream.synchronize()` completes the allocations.
4. Scalars are moved into `translated_expression::owned_literals`.
5. At end of for-loop body, `translation_stream` goes out of scope —
   `cudaStreamDestroy(handle)` fires.
6. Each scalar's `device_buffer::_stream` field still holds the now-invalid
   `cudaStream_t` handle.
7. At the **next** `QueryBegin` (any subsequent DuckDB query), the engine
   calls `task_creator_->reset(false)`, which clears
   `_parquet_scan_operator_global_state_map`, destroying
   `_translated_filter_by_device` and all `translated_expression` objects.
8. Scalar destructors call `cudaFreeAsync(ptr, stale_stream_handle)` →
   **SIGSEGV**.

Key detail: the SIGSEGV fires during the *second* query's QueryBegin, not
during the first query that runs the parquet filter. This explains the
test-ordering sensitivity observed in Phase 10-01 bisect.

## Fix Description

Two-part fix, 36 LOC added:

### Part 1 — `gpu_expression_translator.hpp`

Added `std::optional<rmm::cuda_stream> owned_stream{}` field to the
`translated_expression` struct, declared **before** `owned_literals`.

```cpp
struct translated_expression {
  cudf::ast::tree tree{};
  // owned_stream MUST be declared before owned_literals:
  // C++ destroys members in reverse declaration order, so stream is
  // destroyed AFTER scalars — cudaFreeAsync(ptr, stream) fires before
  // cudaStreamDestroy(stream).
  std::optional<rmm::cuda_stream> owned_stream{};
  std::vector<std::unique_ptr<cudf::scalar>> owned_literals{};
  ...
};
```

Using `std::optional` avoids creating a stream eagerly on every
`translated_expression` construction — the stream is only allocated when
explicitly set by the parquet scan constructor.

### Part 2 — `sirius_physical_parquet_scan.cpp`

After the translator completes and `translation_stream.synchronize()`,
the stream is **moved into** `translated->owned_stream` before emplacing
into `translated_filter_by_device`:

```cpp
rmm::cuda_stream translation_stream;
gpu_expression_translator translator(translation_stream.view(), ...);
auto translated = translator.translate_expression_with_names(...);
translation_stream.synchronize();
if (!translated) { ... }
// Transfer ownership: stream lives as long as the scalars it allocated.
translated->owned_stream = std::move(translation_stream);
translated_filter_by_device.emplace(device_id, std::move(*translated));
```

After the move, `translation_stream.stream_` is null and its destructor
is a no-op. The stream now lives in `translated_expression::owned_stream`,
which is destroyed **after** `owned_literals` due to declaration order.
