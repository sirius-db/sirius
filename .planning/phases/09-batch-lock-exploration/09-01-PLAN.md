    **LOCK-01 Functional Diff Analysis (go/no-go: GO per D-01):**

    The key behavioral differences between `lock_or_prepare_batch` (lines 69-117) and
    `convertible_data_batch::convert()` are:

    1. **In-transit lock:** `lock_or_prepare_batch` manually calls `try_to_lock_for_in_transit()`,
       `convert_to<>()`, and `try_to_release_in_transit()`. `convert()` does all three internally.
       Resolution: Per D-02, remove the manual in_transit handling from `lock_or_prepare_batch`
       and let `convert()` handle it.

    2. **Contention case (lines 77-81):** When another thread holds in_transit, `lock_or_prepare_batch`
       falls back to `wait_to_lock_for_processing`. `convert()` returns `false`. Resolution: When
       `convert()` returns false, the outer while loop will re-attempt `wait_to_lock_for_processing`
       on the next iteration (since lock_result.success stays false and status stays memory_space_mismatch).
       This preserves the retry behavior.

    3. **Single target vs vector:** `lock_or_prepare_batch` has one target space. `convert()` takes
       `vector<memory_space*>`. Resolution: Wrap the single target in a one-element vector:
       `std::vector<cucascade::memory::memory_space*>{const_cast<cucascade::memory::memory_space*>(target_space)}`.
       The const_cast is needed because `convert()` takes non-const `memory_space*` while
       `lock_or_prepare_batch` receives `const memory_space*`. This is safe because `convert()` does
       not modify the memory_space object.

    4. **Reservation checks:** `lock_or_prepare_batch` skips reservation; `convert()` does polite
       reservation via res_mgr. Resolution: Per D-03, thread `res_mgr` to the call site. The
       reservation check is a net improvement (polite reservation before allocating).

    5. **Error handling:** `lock_or_prepare_batch` rethrows `rmm::out_of_memory`; `convert()` also
       rethrows exceptions after restoring state. Both propagate OOM. Resolution: Compatible.
       The caller's OOM catch in `gpu_pipeline_task.cpp` (line 326) still works.
