Close Gap 2 from Phase 02 verification: remove all redundant explicit `cucascade::data_batch::to_idle()` calls from Phase 2 files.

The cucascade RAII accessor types (`read_only_data_batch`, `mutable_data_batch`) now have destructors that automatically transition the batch back to idle state and release the lock (added in commit 25dbc8c7). This means every explicit `to_idle(std::move(ro))` call is redundant -- the destructor fires when the accessor goes out of scope or is destroyed during stack unwinding.

Removing these calls eliminates the `[[nodiscard]]` compile errors under `-Werror` (since `to_idle` returns `shared_ptr<data_batch>` which was being discarded) while also simplifying the code.

```cpp
// to_idle just copies _batch and returns it; the accessor destructs when the function returns
[[nodiscard]] static std::shared_ptr<data_batch> to_idle(read_only_data_batch&& accessor);
[[nodiscard]] static std::shared_ptr<data_batch> to_idle(mutable_data_batch&& accessor);
```

Key insight: `to_idle(std::move(ro))` is equivalent to just letting `ro` destruct.
The destructor releases the shared/exclusive lock and transitions state to idle.
Since no call site uses the returned `shared_ptr`, the `to_idle` call is purely redundant.

The cucascade RAII accessor types (`read_only_data_batch`, `mutable_data_batch`) have destructors that automatically:
- Decrement `_read_only_count` and set state to `batch_state::idle` (for `read_only_data_batch`)
- Set state to `batch_state::idle` (for `mutable_data_batch`)
- Release the shared/exclusive lock via `_lock` member destructor

Every `cucascade::data_batch::to_idle(std::move(ro))` call in these files is redundant because:
1. The call moves `ro` into `to_idle()` which copies `_batch`, then `ro` destructs inside `to_idle()` -- same as just letting `ro` destruct in the caller
2. No call site uses the returned `shared_ptr<data_batch>`
3. The `[[nodiscard]]` attribute causes compile errors under `-Werror` when the return value is discarded
