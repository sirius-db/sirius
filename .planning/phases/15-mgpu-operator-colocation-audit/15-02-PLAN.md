From `src/pipeline/task_scheduler.cpp` (lines 149-160) — where the counter is reset:
```cpp
void task_scheduler::prepare_for_query(duckdb::shared_ptr<planner::query> query)
{
  _scan_executor->drain_leftover_tasks();
  for (auto& [device_id, gpu_exec] : _gpu_executors) {
    gpu_exec->drain_leftover_tasks();
  }
  // Reset SCHED-RR counter ...
  _no_pref_rr_counter.store(0, std::memory_order_relaxed);
  // ...
}
```

This means: **the test must call `set_no_pref_rr_counter_for_testing(N)` AFTER `prepare_for_query` runs but BEFORE the first task dispatch hits `management_eventloop`'s round-robin block.** Easiest harness: subclass scoped_mgpu_env, or expose a hook from `gpu_execution`'s entry point. Cleanest: have the test driver call set_no_pref_rr_counter_for_testing() inside a callback invoked between query setup and execution.

Practical alternative if the timing-hook approach proves too fragile: have the test issue N "warm-up" no-op queries before the real query, where N == desired_offset. Each warm-up query consumes one round-robin slot. This sidesteps the timing problem entirely and uses the existing API surface. Planner recommends this approach; setter is added only if warm-up approach proves insufficient. Decision boundary: if Step 2.A's warm-up sketch implements in <30 lines, use that and SKIP the setter; commit the setter only if Step 2.A is over-complex.

    ```cpp
    /**
     * @brief Inject an initial value into the SCHED-RR round-robin counter.
     *
     * For testing/stress only. Intended to verify that the SCHED-RR
     * distribution path (and the per-task-device contract documented in
     * `docs/super-sirius/pipeline-execution.md`) is correct under
     * arbitrary counter starting offsets — catches hash-bucket-order
     * dependent bugs and off-by-one drift that a counter starting at 0
     * each query might mask.
     *
     * Must be called AFTER `prepare_for_query` (which resets the counter
     * to 0) but BEFORE the first task is dispatched into
     * `management_eventloop`. Concurrent calls are safe (atomic store).
     */
    void set_no_pref_rr_counter_for_testing(size_t value) noexcept
    {
      _no_pref_rr_counter.store(value, std::memory_order_relaxed);
    }
    ```

    The implementation is inline in the header (single-line atomic store; no need for a .cpp definition). This avoids touching the cpp file and the linker's TU graph for a 1-line method.
