# S3 integration test scaffolding

Local MinIO + fixture tooling for the Catch2 `[s3][integration]` tests,
including the semantic end-to-end `[s3][parquet][integration]` test which
reads a parquet object through Sirius's S3 pipeline and parses the bytes with
DuckDB to verify row-level correctness.

## What this gives you

- A pinned MinIO container exposing S3 at `http://127.0.0.1:9000`.
- A fixture generator (`generate_fixtures.py`) that writes a 16-byte text blob,
  a 20 KiB deterministic binary blob, and an 8 MiB deterministic binary blob
  under `test/integration/s3/fixtures/local/`. If `pyarrow` is installed it
  also writes a 256-row patterned parquet (`small.parquet`); otherwise that
  step is skipped with a warning and the parquet test auto-skips.
- A `fixtures.sh` script that uploads everything to MinIO via the `mc`
  container image so tests can bit-compare (and parse) S3 reads against the
  local copy.
- `env.sh` that exports the `SIRIUS_TEST_S3_*` variables consumed by
  `test/cpp/io/s3/test_s3_ioctx.cpp`, `test_s3_integration.cpp`, and
  `test_s3_parquet_integration.cpp`.

## Requirements

- Docker (engine + compose plugin).
- Python 3.9+ (stdlib suffices for the binary blobs).
- `pyarrow` (optional; only required for `small.parquet` and the
  `[s3][parquet][integration]` test). Install via `pip install pyarrow`.
- `curl` (used by `fixtures.sh` for readiness probing).

## Typical flow

```bash
# Bring MinIO up and populate fixtures.
make s3-up

# Run the Catch2 S3 integration tests against MinIO. This tag filter also
# selects [s3][parquet][integration] since Catch2 tags AND together. env.sh
# is sourced for you by the recipe and points tests at the local MinIO.
make s3-test            # alias for s3-cpp-test
make s3-cpp-test        # equivalent

# Or run manually:
source test/integration/s3/env.sh
build/release/extension/sirius/test/cpp/sirius_unittest "[s3][integration]"

# Tear down (the `-v` in `down -v` also removes the named volume).
make s3-down
```

## Pinned image versions

The compose file pins both images to exact release tags rather than `:latest`
so the same sirius commit produces reproducible test behavior over time:

| image | tag |
|---|---|
| `minio/minio` | `RELEASE.2025-04-22T22-12-26Z` |
| `minio/mc`    | `RELEASE.2025-04-16T18-13-26Z` |

To bump: replace both tags, run `make s3-up` locally, and confirm
`make s3-test` still passes. Keep the two tags close in age — `mc` command
surface changes occasionally and mixing a very new `mc` with an older server
can break the `mc mb --ignore-existing` flag the script relies on.

## Fixtures

Regenerated by `generate_fixtures.py` on every `make s3-up`. Output is
deterministic (seeded PRNG for binary blobs; closed-form pattern for parquet)
so a second run produces identical files and the sha256 manifest stays stable:

| file | size | purpose |
|---|---|---|
| `hello.txt` | 16 B | HEAD + tiny-range read |
| `small.bin` | 20 KiB | bit-equal full-object read via `datasource_factory` |
| `medium.bin` | 8 MiB | multi-range reads at odd offsets |
| `small.parquet` | ~few KB | semantic end-to-end: read via `datasource_factory`, parse with DuckDB, assert patterned rows. Only generated if `pyarrow` is installed. |

`small.bin` / `medium.bin` are opaque deterministic byte blobs, not real
parquet — the byte-equality tests in `test_s3_integration.cpp` do not invoke
a parquet reader.

`small.parquet` has schema `id INT32, v INT64, s VARCHAR` and 256 rows with
values derived in closed form (`v = id * 2654435761`, `s = "row-<id:04d>"`),
so the C++ test regenerates expected values without reading the local file.

A sha256 manifest is written to `fixtures/local/MANIFEST.sha256`.

## Caveats

- MinIO signs with `us-east-1` by default; if you set `MINIO_REGION` to
  something else in the compose file, also bump `SIRIUS_TEST_S3_REGION`.
- `fixtures.sh` uses `--network=host` on Linux and `host.docker.internal` on
  macOS/Windows to let `mc` reach MinIO on the host network. If you run MinIO
  inside a non-host-network compose stack, override `SIRIUS_TEST_S3_ENDPOINT`
  to the compose-internal name and drop `--network=host`.
- When `SIRIUS_TEST_S3_*` is not set the integration tests `SUCCEED` with a
  skip message rather than failing — this is intentional so the default
  `sirius_unittest` run stays green on CI runners without docker.
- The `[s3][parquet][integration]` test additionally skips when
  `small.parquet` is missing locally (pyarrow was not installed at
  `make s3-up` time). Install pyarrow and rerun `make s3-up` to enable it.
- `env.sh` also exports `SIRIUS_CONFIG_FILE` pointing at `sirius.yaml` in this
  directory. It caps Super Sirius's startup GPU/host reservation at 256/128
  MiB so `require sirius` in SQL tests in this area won't OOM on GPUs that
  don't have ~90% free. The parquet-integration test spins up a bare
  `duckdb::DuckDB` and does not touch the reservation manager. If you've
  already set `SIRIUS_CONFIG_FILE` the `env.sh` assignment is a no-op.
