Source and scope
---------------
Use a clean, isolated checkout of https://github.com/kevkrist/sirius, branch
fix/cucascade-merged-api-migration. Fetch and check out the branch as shown below;
all four review fixes and their regression tests are included in the branch.
Record the exact full SHA with `git rev-parse HEAD` after checking it out.
Read AGENTS.md and preserve existing work. Keep validation changes uncommitted;
report failures before modifying code.

Requirements
------------
Expose at least two assigned GPUs to CUDA, preferably three. Three are needed
for the separate three-GPU fan-out test. The first two visible GPUs should have
working pool peer access so the completion-failure tests exercise asynchronous
peer copies instead of skipping. Forced HOST-staging tests cover the other route.
Respect the host's GPU allocation; do not remove its visibility mask blindly.

Use a compatible Pixi environment consistently for configuration, build and tests.
For CUDA 12 hosts, substitute `pixi run -e cuda12` for `pixi run` throughout.
Do not mix environments in an existing build directory.

Prepare the isolated checkout
----------------------------
git fetch https://github.com/kevkrist/sirius.git fix/cucascade-merged-api-migration
git switch --detach FETCH_HEAD
git submodule update --init --recursive
git rev-parse HEAD
git -C cucascade rev-parse HEAD
nvidia-smi -L

The cuCascade revision should be 1a9281093a0fe49634594d541d7ce327129f53d6.
Also record CUDA_VISIBLE_DEVICES and confirm CUDA itself sees the assigned GPUs.

Acceptance and reporting
------------------------
1. Verify remote sparse and dense materialization returns correct integers and
   strings, including repeats and ordering, with automatic and forced HOST routes.
2. Verify replicas work on destination GPUs, reservation refusals remain optional,
   and actual managed pool grants/copies preserve bytes in both directions.
3. All seven replica fault cases must execute their substantive checks. A skipped
   test or an early return due to unavailable pool access is NOT validation.
   Confirm enqueue failure plus secondary drain failure preserves the first error;
   completion failure still drains later pending copies; failed membership fan-out
   installs no new replicas; zone-map resource refusals skip but CUDA failures throw.
4. Verify the HOST fallback uses two normal synchronization calls independently of
   block count, and partial batch submission is drained before staging is released.
5. Verify the issue #4 regression clears real CUDA last-error state while retaining
   the original exception diagnostic.
6. List every skip/warning/early return explicitly. With only two GPUs, the
   three-GPU fan-out test is expected to remain unvalidated. Some existing tests
   warn and return rather than using Catch's SKIP; inspect the logs, not just exit 0.
7. Return source/submodule SHAs, working-tree status, GPU models/count/topology, driver and
   CUDA versions, selected Pixi environment, exact commands, results and logs.
   Distinguish actual multi-GPU execution from classifier-only or skipped coverage.

These runs validate the selected CUDA/toolchain branch only. The CUDA <12.8 loop
is not exercised by the supported CUDA 12.8+ or CUDA 13 environments.
