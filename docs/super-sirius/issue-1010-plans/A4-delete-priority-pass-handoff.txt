## Background
Sirius's scheduler has a pass that prioritizes dispatching build-side scan tasks for
hash joins that publish dynamic filters, so a filter publishes before probe-side scans
start consuming it — intended to improve filter coverage. Issue #1014 suspected this
pass "can probably just go away." We measured it (issue #1124): three configs
(no filters / pass on / pass off) across TPC-H Q5,Q7,Q8,Q9,Q21 and a `many_join` query
at SF300. Result: the pass gives ZERO coverage benefit (filters already publish before
any probe row is consumed, even with the pass on) and costs 9–25% wall time plus large
run-to-run variance. Verdict: delete it.
