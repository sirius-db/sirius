## 0. Purpose and the generality rule

Root cause (ANALYSIS-oom-edge-2cn-staging.md §1 l.9-19; REVIEW §3.1 l.99-104): the FE plans every FILES() scan at cardinality 1 (StatisticsCalculator.java:669-672) and therefore hash-partitions the largest input of the first join; the CN executes that shuffle as a barrier (receiver dispatched only after every sender's EOS, local_exchange.rs:573-611; export providers only after run(), sirius_ffi.cpp:1264-1270; engine.rs:731-760), so each CN materializes local half + inbound half = rows x row width (84/96/120 GB for widths 28/32/40 B at 3.0e9 rows) against an 81.6-90.2 GB pool. The staging arena is a bystander (peak live 4.49 of 8 GiB; REVIEW l.38-42). Three work packages attack this from three sides: WP1 bounds every frame and batch in bytes (headroom + robustness), WP2 gives the FE real statistics so its existing broadcast/shuffle rule can work and lets the engine wire runtime filters from small stream-fed builds, WP3 bounds receiver admission and then removes the EOS barrier. **Generality rule:** every mechanism is expressed in rows, bytes, distinct-value bounds, provenance, destinations, node counts and budgets; no code path, gate, knob or log level may key on a table, column, constant, query id or "fact/dimension" role. TPC-H SF1000 q05/q08/q09 at 2 CNs are acceptance instances that appear as rows of an all-22 table, never as gate text. Where a source proposed something query-specific (hinted `JOIN [BROADCAST]` SQL, "filter PART keys before LINEITEM", "1 GiB operator_params", "raise broadcast_row_limit to 50M") it is translated to the mechanism it exemplifies (§7) or dropped.

## 3. WP1 -- Size-bounded exchange frames and engine batches, independent of arena and pool

**Goal.** Every frame and producer batch is bounded by an explicit byte limit enforced consistently at the packer, TX and RX, so any table's batches (any width, fan-out mode, join order) transfer through any arena without EXPORT_CAPACITY_EXCEEDED, whole-parent reload bursts or arena growth; the 8 GiB spent on a 16 GiB arena returns to the pool. WP1 is headroom + robustness, not the q08 fix (q08's largest frame 1.09 GB already fits; REVIEW l.135; ANALYSIS l.117).

**Principles.** Bound computed from bytes and capacities (receiver max_batch, TX pack reservation, configured batch bytes, destinations). Frames are self-contained packed tables split by row ranges, never byte chunks (10:28); measured `chunked_pack::get_total_contiguous_size` (sirius_ffi.cpp:1168) is the authority. The size decision precedes the whole-parent reload at :1121-1145; pack scratch (pool, :1166-1167) accounted at measured size; payload lives in the arena lease (:1187-1195) and is never double-charged. The enforcement points move together: packer cap :1176-1183, grant-reply max_batch check pipeline.rs:397 (kept as backstop), TX reservation/allocated>reserved :610-623/:654-667, RX length>max_batch exchange_protocol.rs:259-263, RX concurrency caps :284-289 (live <= A/2, per-peer <= A/4, 64 active, 32 per peer); RX in-flight per peer = min(window, floor((A/4)/ceil256(frame)), 32) (RX charges length rounded to 256 B, no slack, :279-283; the grant asks for batch.len, pipeline.rs:489); TX in-flight (all peers) = floor((A/2)/pack_reservation) = 2 today (a full pack_reservation per frame irrespective of frame size, :610-613), = floor((A/2)/(bound + 8 MiB)) once SIRIUS_CN_TX_RESERVE_TO_BOUND=1. Negotiation alone is not the lever: on symmetric arenas min(A/4 - 8 MiB, peer max_batch) reproduces today's value (exchange_protocol.rs:162-163; pipeline.rs:838, :311); the lever is the explicit bound + CN batch clamp. WP1 never adds a sink-side queue that waits on a post-run drain (10:35). Cancellation mid-parent is Err, never EOS. Every change has its own kill switch and TUNABLES.md entry.

## 4. WP2 -- Statistics-driven plan shape (FE) and runtime filtering (engine) for any FILES() workload at N CNs

**Goal.** The FE decides broadcast vs shuffle, build side and join order for FILES() tables from real cardinalities, bounded column statistics with provenance, predicate selectivities and a byte budget that (a) counts the real execution nodes and (b) is matched to the GPU build limit; the engine accepts any small declared build stream as dynamic-filter evidence so large probe scans are pruned before crossing an exchange whenever the plan places them beside their join.

**Principles.** Fix inputs before rules: FILES() plans at 1 row / unknown columns (StatisticsCalculator.java:669-672); fan-out uses ctx.getAliveBackendNumber() (EnforceAndCostTask.java:315; CostModel.java:421-423), BE-only (SystemInfoService.java:1047-1049) = 0 on a CN-only shared-data cluster (arms/GATEA-2cn/compute-nodes.txt), so every broadcast is costed as one node. The one rule change is the byte budget in CostModel.java:419-428 with the row guard at EnforceAndCostTask.java:324-327 relaxed. Unknown is not one and derived is not measured: ColumnStatistic.unknown() has NDV = 1 (ColumnStatistic.java:32-33) so joins through unknown columns cannot shrink (estimateInnerJoinStatistics :1711); introduce DERIVED provenance, never a fabricated exact value (12:53-55). The plan predicate states necessary conditions (no over-budget broadcast; no shuffle of a side > R x a budget-fitting partner) and never mandates BROADCAST; it reads only cardinality x sum(avgRowSize) (Statistics.java:88-105), never the TPC-H prefix map (explain_summary.py:15). Pass = bytes on the wire and rows removed fall (external l.214), not plan text.
