# Quent Export Verification (WS18)

Independent verification rig for hwsim's quent-ndjson export (WS17,
`tools/hwsim/sim/hwsim/export_quent.py`, [quent-export.md](quent-export.md)).
The rig derives its contract from the **Rust analyzer's deserialization
types** — not from the exporter's own assumptions — and proves each layer:
schema → analyzer ingest → server/UI discovery. Everything lives in
`tools/hwsim/export-verify/` plus one new analyzer example.

## The rig

| piece | what it proves | how to run |
|---|---|---|
| [`export-verify/SCHEMA.md`](../export-verify/SCHEMA.md) | The contract itself: 19 entity types, envelope, FSM seq/transition rules, id graph, session layout, importer sharp edges, and 9 documented reality-vs-types divergences | read it |
| [`export-verify/validate_quent_session.py`](../export-verify/validate_quent_session.py) | Line-level contract conformance (stdlib Python): layout, envelope, required fields/types/enums, seq contiguity + entry/exit/transition legality, per-id timestamp monotonicity, id-graph + resource-tree integrity, epoch-ns sanity | `python3 tools/hwsim/export-verify/validate_quent_session.py <session_dir> [--simulated] [--allow-legacy]` |
| [`export-verify/ingest_check.sh`](../export-verify/ingest_check.sh) | The actual Rust analyzer accepts the session: per-stream raw-lines vs deserialized-events (catches the importer's **silent truncation**), model build, query list, non-empty resource tree | `tools/hwsim/export-verify/ingest_check.sh <session_dir>` |
| `rust/crates/telemetry/analyzer/examples/ingest_check.rs` | (the Rust half of the above; also `print_resource_tree` renders the viewer's tree) | built automatically by the script (CPU-only; first build is slow) |

Why the truncation counter matters: the quent ndjson importer **stops a
stream at the first line that fails deserialization and logs the error to a
tracing subscriber that the analyzer examples/server do not print** — a bad
line never fails ingestion, it silently deletes the rest of that entity's
events. Counting is the only black-box way to see it.

## What was validated at each layer

### 1. Schema layer — validator calibrated on real sessions first

| session | model | result |
|---|---|---|
| `tools/hwsim/experiments/traces/LB/019fd052-…` (30,208 events, 15 queries) | current (post-WS9) | **PASS: 0 errors, 0 warnings** |
| worktree `telemetry_data/019fd006-2d8f-…` (WS9 demo, 135 io_request lines) | current | **PASS: 0 errors, 0 warnings** |
| main-repo `telemetry_data/019fd008-…` | pre-WS9 | **PASS with `--allow-legacy`** (170 legacy warnings) |
| `traces/E2-lo-q9/019fcf46-…` (pressured) | pre-WS9, **stripped subset** | correctly rejected: empty engine/resource streams ⇒ 29 dangling-ref errors; it is genuinely not a loadable session |

Calibration corrections applied to the validator (reality over reading):
`task.Preparing.origin_tier/target_tier` are free-form Strings (`SOURCE`,
`UNKNOWN` observed); the engine emits `BatchProcessing→BatchPackaged` under
OOM reschedule even though the `fsm!` table omits it (the analyzer never
validates transitions — it time-orders events).

### 2. Analyzer layer — ingest rig calibrated on real sessions

- LB session: **PASS** — all 18 streams import 1:1 (30,208/30,208 events), model
  builds, 15 queries listed, resource tree = 1,237 nodes.
- Pre-WS9 session (`019fd008`): **FAIL, by design** — empirically proves the
  current analyzer truncates old-shape streams (task 124→24, data_batch
  160→0, batch_placement 60→0) while the session still "loads" with plans and
  resource tree intact. This is the exact failure mode of defect 1 below.

### 3. WS17 export verification (fresh exports, generated by this rig)

Generated from the B1 trace with the landed CLI:

```bash
cd tools/hwsim/sim
python3 -m hwsim simulate ../experiments/traces/B1/019fcecb-… \
    --query-label B1_tpch_q21_iter1_iter1 --knob gpu_compute=0.5 --export-quent <out>
python3 -m hwsim simulate … --export-quent <out>          # @baseline variant
```

**Validator (`--simulated`):** everything passes — layout, envelope,
id graph, per-entity seq/timestamps, resource-tree chains, engine
`hwsim-sim`, `hwsim.simulated/source_session/source_query/knob.*`
attributes, `@knob=value` / `@baseline` labels, v7 uuids — **except one
defect class**: 35,786 missing-WS9-field errors (see below). With
`--allow-legacy`: **0 errors**.

**Analyzer ingest:** **FAIL** — confirmed the predicted truncation on the
export itself: task 22,294→6, data_batch 27,396→0, batch_placement
41,874→0 events. The skeleton (engine, query `…@gpu_compute=0.5`, 52
operators, 165-group resource tree) ingests; every task/batch timeline is
silently dropped.

**Server smoke** (side-by-side dir = real LB session + 2 simulated sessions;
`sirius-telemetry-server --features ui` on a scratch port):

- `GET /api/engines?with_metadata=true` lists all three engines: `siriusDB`
  (real) and two `hwsim-sim` with full `hwsim.*` attributes — the simulated
  engine is discoverable and distinguishable exactly as intended.
- `GET …/query-groups` → `…/queries` on the simulated engine returns the
  query `B1_tpch_q21_iter1_iter1@gpu_compute=0.5`, `completed_s=34.8`
  (2× the traced 17.5 s wall — knob arithmetic visible end-to-end).
- `GET …/query/{id}` (the UI's query bundle) returns HTTP 200 with plan
  tree + resource tree.
- **t0 anchoring verified exact**: simulated `query.Executing` timestamp ==
  the source trace's `Executing` timestamp (Init/Planning pads at −1 ms/−0.5 ms),
  so real and simulated sessions share a comparable time axis.
- Server started and shut down cleanly (short-lived, non-default ports).

### Defect list filed against WS17 (one defect)

1. **Pre-WS9 event shapes break the current analyzer** (silent, total loss of
   task/data_batch/batch_placement timelines).
   - Event/fields: `task.Computing.input_rows`;
     `task.Finalizing.output_rows`, `.output_bytes`;
     `data_batch.Constructed.producer_task_uuid`, `.num_rows`, `.num_columns`;
     `batch_placement.BatchRegistered.producer_task_uuid`.
   - Example line (first casualty, sim export task stream line 7):
     `{"state":{"Computing":{"instance_name":"GPU_SCAN(13)…","current_operator_id":13,"input_bytes":…,"peak_allocated_bytes":0}}}` — no `input_rows` ⇒
     serde `missing field` ⇒ stream truncated at event 6 of 22,294.
   - Why it slips past WS17's round-trip: the sim's own Python parser treats
     WS9 fields as optional (per `ws9-new-fields.md`); the Rust analyzer's
     serde structs have **no defaults** — the "optional" contract was for the
     Python parser only.
   - Note the exported `model.qmi` honestly records the pre-WS9 source model
     commit (`b77aa438`), so the export is *self-consistent* — but
     `pixi run quent` compiles the analyzer from the **current** tree, and a
     side-by-side dir mixing new real sessions with pre-WS9-shaped simulated
     ones has no single analyzer that parses both.
   - **Fix (small):** emit the WS9 fields with their documented unknown
     markers — `input_rows=0`, `output_rows=0`, `output_bytes=0`,
     `num_rows=0`, `num_columns=0`, `producer_task_uuid=nil` (the engine
     itself uses exactly these for unknown). This does not "invent
     measurements"; 0/nil *is* the schema's unknown value. Re-run this rig
     after: `validate_quent_session.py <dir> --simulated` must report 0
     errors without `--allow-legacy`, and `ingest_check.sh <dir>` must PASS.

### WS17's eight unilateral decisions — cross-checked

| decision | verdict |
|---|---|
| 1. deterministic uuid7 (ms \| ver7 \| counter \| seeded hash) | OK — v7 version nibble validated; ids resolve; deterministic session dir name parses as uuid (server discovery requirement met) |
| 2. 0 ns scheduler-queue dwell (Queued/Routing/Queued share a timestamp) | OK — the contract requires non-decreasing timestamps only; the analyzer's time-ordered collector uses a stable sort, so file order (== seq order) is preserved for ties |
| 3. `Reserving.input_basis=input`, `peak_estimate=requested`, granted=min(...) | OK — plain u64s; semantics are sim-honest and within type contract |
| 4. no-Preparing tasks export `origin_tier=target_tier="GPU"` | OK — tier fields are free-form Strings (real traces even use `SOURCE`/`UNKNOWN`) |
| 5. producer-less batches Constructed at t0−10 ms / consumer-less drained `query_end` | OK — `query_end` is a legal enum; pre-t0 timestamps are fine (analyzer spans clamp); no nil uuids found in the exported data_batch stream |
| 6. `origin` always `operator_output`; timestamps clamped monotone per entity | OK — legal enum value; monotonicity verified across all 91,794 events |
| 7. greedy interval-colouring thread bindings | OK — every executor-thread/manager-thread usage resolves; per-thread intervals are non-overlapping by construction and nothing in the contract requires matching real bindings |
| 8. synthetic Init/Planning pads (t0−1 ms/−0.5 ms), `worker-hwsim` | OK — legal query FSM; verified Executing lands exactly on the traced t0 |

### WS20 additions (physics-retimed export) — cross-checked

| decision | verdict |
|---|---|
| 9. `Routing.instance_name` carries `qprio=<rank>` (dispatch order; sim enqueue timestamps do not encode the traced queue priority the engine dispatched by) | OK — free-form String; analyzer ingests; validator clean. REQUIRED for round-trip fidelity: without it a re-sim of B1 q9's physics export repacked +67% (order-sensitive schedule); with it 0.00% |
| 10. `PHYS::PREP` pseudo-operator exports `current_operator_id = u32::MAX` (no plan operator) | OK — `current_operator_id` is `u32` in the analyzer model (`task.rs`); `-1` was rejected by serde and silently truncated the whole task stream (16,976 → 6 lines ingested), u32::MAX ingests 16,976/16,976 |
| 11. physics label token `...@<knobs>,physics` / `@baseline,physics` + `hwsim.physics*` engine attrs | OK — validator's sim-label heuristic taught the `,physics` token; attrs are plain String/F64/I64 custom_attributes |

Only the WS9-field omission (in the coordinator's "deliberate omissions"
list, cross-checked above) breaks the analyzer; `io_request` /
`InTransit` / `Downgrading` omissions and `peak_allocated_bytes=0` are all
contract-clean.

## How to run the rig (recap)

```bash
# 1. schema conformance (simulated exports)
python3 tools/hwsim/export-verify/validate_quent_session.py <session_dir> --simulated

# 2. analyzer ingest (compiles the analyzer crate on first use; CPU-only)
tools/hwsim/export-verify/ingest_check.sh <session_dir>

# 3. real sessions: same two commands; add --allow-legacy for pre-WS9 traces
```

## End-user side-by-side workflow (real + simulated in one viewer)

```bash
# 1. put a real session and the simulated exports in one directory
mkdir -p /tmp/side-by-side
cp -r <telemetry_output_dir>/<real-session-uuid> /tmp/side-by-side/
cd tools/hwsim/sim
python3 -m hwsim simulate <trace_dir> --query-label <L> \
    --knob gpu_compute=0.5 --export-quent /tmp/side-by-side

# 2. serve them together
pixi run quent /tmp/side-by-side        # UI at http://localhost:8080

# 3. in the UI's engine picker, `hwsim-sim` engines sit next to `siriusDB`;
#    the hwsim.* custom attributes identify source session/query and knobs,
#    query labels carry the `@knob=value` suffix, and the simulated t0 is
#    anchored to the traced query start so timelines align.
```

Headless equivalent of step 3:
`curl -s "http://localhost:8080/api/engines?with_metadata=true"`.
