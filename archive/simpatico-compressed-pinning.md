**Compressed pinning already exists in dev** (since #937/#1325/#1334, tier-agnostic): `SET pin_table_compression=true; SET pin_table_input_compression_plan_dir='<dir>'` — plan files named `<table>.txt`, one "---"-separated DSL block per FULL-table column in schema order (`select_plan_blocks` picks pinned subsets; a table with no file pins uncompressed). Decompress at scan time via `compressed_host_representation → gpu_table` converter, column-parallel (`compression_column_threads`, default 4). Checked-in SF1000 plans: `src/compression/simpatico_codegen/plans/tpch_sf1000/`. **ans >2GiB bug:** byte-codecs that materialize channels as cudf columns (ans; NOT nvcomp-backed snappy/lz4/deflate/bitcomp which chunk internally) CRASH on chars channels > 2^31 bytes ("Column size cannot be negative", int32 overflow). Engine pin batches are scan_task_batch_size (5GB) of the PINNED SUBSET → a narrow pin (q18 customer = custkey+name) can put ~4.2GB of chars in one batch. Rule: ans only where the column's TOTAL chars < 2GiB (supplier-scale). Explore alternates measured on 2GiB-trimmed prefixes hide this. Also lz4 on text decodes at only 86 GB/s (unlike its 740 on delta-keys); dictionary/str_split on strings columns are large-safe (cudf int64 offsets).
